# anki-tg-bot 🧠

A Telegram spaced-repetition bot — Anki in your chat. Built for learning German vocabulary (B2 → C1) and interview questions, but decks can hold anything.

- **FSRS-6** scheduling via [`ts-fsrs`](https://github.com/open-spaced-repetition/ts-fsrs) — the same algorithm modern Anki uses. Buttons show the real next interval: `❌ Снова · 1м  😐 Трудно · 6м  ✅ Хорошо · 10м  🚀 Легко · 4д`.
- **Note → cards**: one German word becomes `DE→RU`, `RU→DE` and, for nouns, an auto-graded **der / die / das** quiz. Siblings are buried for the day.
- **Per-deck reminders**: own time and threshold per deck, once per study day, 💤 snooze. No streaks, no guilt.
- **Safe imports**: JSON contract with dry-run preview; re-importing updates content and **never resets progress**. `/export` = full backup in the same format. Progress migration from Noji/Anki via the optional `srs` block.
- **Leech detection** (8 lapses → suspended, with a hint to rephrase), undo of the last answer, daily limits, Anki-style study day (rollover at 04:00 in the user's timezone, DST-safe).
- **Multi-tenant from day one** — every row is scoped by user; a `plan` column is ready for a future subscription.

## Stack

NestJS 11 · grammY · Drizzle ORM · PostgreSQL · zod · Jest. Hosting: Render (free) + Neon Postgres (free) + cron-job.org (free).

```
src/
  srs/            FSRS wrapper (pure), study-day math (pure), queue & review services
  cards/          note → cards, Telegram HTML rendering (pure)
  import/         zod contract, import/export (idempotent upsert)
  notifications/  reminder decision (pure) + sender, triggered by POST /jobs/tick
  bot/            grammY handlers, stateless callback data (≤ 64 bytes)
  db/             Drizzle schema + migrator
docs/             IMPORT_FORMAT.md, CARD_RULES.md
test/             e2e: real Postgres, real Nest app, fake Telegram API
```

### Design decisions

| Decision | Why |
|---|---|
| No in-process cron | A free Render instance sleeps after 15 min without inbound traffic, so timers would silently not fire. An external cron calls `POST /jobs/tick`; each tick is idempotent. |
| `drop_pending_updates: false` | Answers sent while the instance wakes up must not be lost. |
| Stateless buttons with a version | `r:<card>:<rating>:<version>:<scope>`: double taps and stale messages are rejected by optimistic locking. |
| Conversation state in Postgres | Survives restarts and sleeps (the pending import lives in `bot_sessions`). |
| Drizzle instead of Prisma | Pure TypeScript, no engine binaries, SQL migrations committed in `drizzle/`. |

## Local development

```bash
cp .env.example .env          # BOT_TOKEN from @BotFather, BOT_MODE=polling, DATABASE_URL
npm ci
npm run db:migrate            # applies drizzle/*.sql
npm run start:dev
```

Tests:

```bash
npm run lint && npm run typecheck && npm test
TEST_DATABASE_URL=postgresql://user:pass@localhost:5432/anki_test npm run test:e2e   # the DB is wiped
```

Changing the schema: edit `src/db/schema.ts` → `npm run db:generate` → commit the new SQL.

## Deploy (all free)

1. **Telegram**: create a bot with [@BotFather](https://t.me/BotFather) (`/newbot`) and copy the token.
2. **Neon**: create a project in region Frankfurt and copy the connection string (`…?sslmode=require`). In *Compute settings* set max size to **0.25 CU** and keep scale-to-zero on: the free plan includes 100 CU-hours per month.
3. **Render**: *New → Blueprint* → this repo (uses `render.yaml`). Fill in:
   - `BOT_TOKEN`, `DATABASE_URL`;
   - `PUBLIC_URL` = the service URL, e.g. `https://anki-tg-bot.onrender.com`;
   - `ALLOWED_TELEGRAM_IDS` = your Telegram id (optional; empty = open to everyone).
   `WEBHOOK_SECRET` and `JOBS_SECRET` are generated by Render. Migrations run on every start.
4. **Pinger** (UptimeRobot or cron-job.org), two monitors:
   - keep-alive: `GET https://<service>/health` every **5–10 min** (does not touch the DB);
   - reminders: `GET https://<service>/jobs/tick?secret=<JOBS_SECRET>` every **15 min** (or `POST` with header `x-jobs-secret`).
   Note: Render's 750 free hours are per workspace — one always-on free service per account.
5. Open the bot → `/start` → send a JSON file → `/learn` → `/notify`.

## Decks as code

Deck files live in [`decks/`](decks). On every start (= every deploy) `DeckSyncService` imports them into the owner's account (`OWNER_TELEGRAM_ID` or the first id in `ALLOWED_TELEGRAM_IDS`) and reports the changes in Telegram. Adding cards = commit a JSON file + push. `npm run cards:check` validates all files and flags duplicates (also in CI). The workflow for Claude is described in [CLAUDE.md](CLAUDE.md), the user guide (RU) is in [docs/USAGE_RU.md](docs/USAGE_RU.md).

## Import format

See [docs/IMPORT_FORMAT.md](docs/IMPORT_FORMAT.md). Minimal example:

```json
{
  "schemaVersion": 1,
  "deck": { "key": "de", "name": "Deutsch" },
  "notes": [
    {
      "externalId": "de:gerät",
      "type": "vocab_de",
      "fields": { "article": "das", "lemma": "Gerät", "plural": "die Geräte", "pos": "noun", "translation": "прибор" }
    }
  ]
}
```
